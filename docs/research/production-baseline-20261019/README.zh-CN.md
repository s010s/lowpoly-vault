## 短结论

1. **砂岩的问题首先是用途和造型基准错位，现有证据不能证明它是被面数上限压坏。** 588 tri、34,128 B 仅占现行上限的 4.2% 和 3.41%；生成器直接选择长方体教学露面、规则条带和周期起伏。增加同样的条带只会得到更细的板材。
2. 现有 Skills 已反对“面越少越好”和统一历史档位；近期生产却把自然低模与教学展示混在同一 brief，并给 24 个不同用途资产套用同一预算。优先补齐“自然场景可用性、实际参考像素、正常大小多角度”的明确验收，再允许有可见收益的几何或表面成本。
3. 建议默认交付自然场景里的精致低模，教学剖面另设用途；试行屏幕尺寸×结构复杂度预算。保留当前 1,000,000 B／14,000 tri 生效约束，单独讨论将它们改为版本化 profile 的方式。约 400 KB 是已接受的量级，10 MB 不作为常规交付方向；不建立新的全库固定目标。

## 3. 砂岩：问题链及可执行的下一版 brief 草案

冻结GLB：`1a93b06b2a9a3457f0f11bff876328dc50b5d8c2f3a7a730fe411ebc200b3ac1`。发布版与候选hash一致，2材质、2primitives、零纹理，约0.8×0.505×0.305m。

[build.py](../../../assets/candidates/continuous-small-life-round11-20261018/batch-32/cross-bedded-sandstone/r001/build.py) 第155–178行直接规定：组界0/.165/.335/.505m（三组近等高，非数学上完全等高）；倾率+.30/−.38/+.23；同一矩形裁切范围x±.4m；`spacing=.026`；`front=-.16+.003*((j+g)%3)`，即沿层号循环0/3/6mm阶差。相邻层有真正截切楔形，但外轮廓、等距条纹和三条一循环是人工构图，不是预算用尽后的降级结果。

[reference-access.json](../../../assets/candidates/continuous-small-life-round11-20261018/batch-32/cross-bedded-sandstone/r001/reference-access.json) 明写“no source image pixels viewed”；BGS全文没有定位精确截切依据，补充历史出版物仅搜索摘录，打开失败。文字足以帮助概念识别，不足以决定自然露头的外壳、风化和层理的视觉节奏。原QA确实看了固定及runtime像素，但其判断依据集中在截切楔层；9个相同教学块的排列也没有检验它放进自然场景是否像石头。

**拟议新用途：** `natural-scene-prop / cross-bedded sandstone outcrop fragment`，风格化自然砂岩露头碎块，非特定地点、古水流、年代复原。旧教学版保留历史用途和批准记录；不能仅换标签把它变成新用途合格版。

**新造型义务：** 先定支撑底面、至少两个有因果关系的断裂/风化主平面、非矩形顶缘及一处有方向的破损；层组截切仍可读，但只在自然露面局部出现，绕侧面有体积逻辑。改变组厚、层终止与局部侵蚀节奏，取消覆盖全体的固定0/3/6mm循环。保留安静的大面，避免全体随机噪声。规则层段可以存在，不把“自然”误解成每条都必须随机。

**预算起点：** 典型80–240px，最近480px；先试1.5k–6k tri、约100–400KB，允许更低而视觉通过。需要更高时说明改善的是哪处断面、缺口或轮廓，先在当前硬帽内评审；不预承诺最终面数。材料色或小原创建色图均可，微浮雕只有在正常大小有贡献才保留。变形主壳可能比逐层封闭楔块更有效，不能以“每条细层必须厚实封闭”作为自然观感的替代品。

**验收草案：** 128/240px正反3/4、左右侧显示石体重量和落地关系；480px确认层理终止与中尺度断面；灰模仍有主壳和截切；中性地面放置一件及三件不同朝向，画面不呈现整齐建筑板材。与已实际看过的自然露头照片比较大中尺度，不复制照片轮廓，不要求一比一地质实测。不按“必须三组”“必须某种古流向”增加科考负担。

## 4. 把用途与事实精度拆成两个轴

| 用途 | 合理的形体 | 不能缺少的证据 |
|---|---|---|
| 自然场景资产（建议默认） | 完整或自然破损的外壳、可摆放底部、侧背面、断裂/风化/生长的中尺度；可有真实露层 | 正常视角多面、局部场景放置、真实对象图片；无说明牌也有可信体积 |
| 教学剖面/标本展示 | 明确切面、规则基底、夸张内部构造可接受；天然板状标本也无需强行扭曲 | brief写明切面与省略部分，内部结构可读，预览/名称不暗示完整自然外形 |
| 场景兼教学的局部露面 | 自然主体加一处解释性露面，必要时另交展示变体 | 两种用途分别判定，展示底座不混进复用GLB；不因多用途多计资产 |

用途另配 `evidence-informed stylized concept / strict reconstruction / fantasy` 等事实范围。自然场景资产不必是严格科学复原；教学模型也不自动更准确。地质剖面、化石薄板、露头层面本身都不是错误。需要纠正的是把局部识别成功等同于所有用途的高品质。

## 5. 待试行软预算：观看条件先于面数

下面是**项目试验起点，不是官方标准，也未改任何gate**。以同一viewport记录最长投影像素L与 `L / viewport短边`，同时记录DPR、CSS/实际framebuffer尺寸、镜头FOV或正交span；不用物理对象大小代替屏幕尺寸。典型和最近支持视距分别声明，画廊近看能力不能冒充场景常驻预算。

| 使用档 | 观看与数量假设 | 简单结构 tri | 多分支/孔洞/薄片/多层结构 tri | 常规GLB软参考 |
|---|---|---:|---:|---|
| 远景/高重复 | L约32–96px；100–300可见副本 | 200–1,500 | 800–3,000 | 20–120KB |
| 常规环境 | L约80–240px；10–50副本 | 800–4,000 | 3,000–8,000 | 60–350KB |
| 近景精致道具 | L约240–480px；1–10副本 | 2,000–6,000 | 6,000–14,000 | 150–500KB |
| 结构复杂近看样品 | L约480–800px；1–3副本 | 单独论证 | 12,000–24,000（含超过旧帽的提案部分） | 300–800KB |

档位有意重叠；同一物体可在不同场景选不同表示。低于区间不自动返工，高于软范围不自动拒收；通过用途义务且无冗余即可。若只能通过微小细节或高倍放大区分A/B，不优先加成本。复杂度按明确连接、转折、负空间和中尺度层级判断，不按生成器创建了多少重复条带判断。

这些起点以已测分布为锚：常规库中位约6k tri/134KB，地质中位5.6k/123KB；fern约7.7k/421KB；conifer约19k/716KB。它们是容量与例外量级的参照，不是品质、帧率或新候选批准证明。高重复植物即使单件好看也可能需要远表示、合批、遮挡剔除；不强制每件三档LOD。若做LOD，实际测试切换和负空间保留。

### 超软预算的短理由单

每件只需一段与一组对照：`asset/revision/hash → 用途/L/副本数 → 现有上限与实际增量（tri/导出顶点/B/纹理/primitive）→ 哪个正常视角的哪个结构改善 → 同镜头A/B → 低成本方案为何不足 → scene或硬件未验证项 → 决策人/日期/profile版本`。

允许理由如“480px侧视主枝连接变折板，增加截面解决转折”“128px层组全靠颜色，增加一处真实侵蚀台阶”。不接受“更精致所以加倍”“还没填满预算”。超软线但在冻结硬帽内，可由制作负责人和独立QA按已授权流程裁定；超冻结硬帽必须先有单独获批的新brief/profile再建候选，不能关校验器、修改历史JSON或把旧FAIL改PASS。

### 对旧14k/1MB的具体建议

- **现在：原样保留。** 数据没有表明1MB正在大范围损害质量；24件最高13,030tri，也不能证明缺陷只来自14k帽。先修用途和结构，再看实际碰帽证据。
- **建议批准后：** 常规profile仍以14k/1,000,000B为安全边界；复杂近看profile可单独试验到24k tri、GLB软参考800KB、1MB以上先hold并报确切成本。超过1MB的交付需要用户逐件决定，当前不提倡全库升至5MB或10MB。
- 14k不适合作为全库不可例外真理：现有针叶树19,052tri；[三角龙受控案例](../../../docs/case-studies/lightweight-triceratops.md)同样14,432tri、轻量建色版471,784B，而1K/2K多图PBR分别2,689,404/7,695,292B。后两者是成本警示，不是今后默认包。
- 用户接受过约400KB量级，记录中的三角龙是471,784B；不把偏好写成精确400,000B硬限，也不将历史接受当作解除了事实、结构或GPU未完成项。

|---|---|---|
| 下载 | GLB总B、几何buffer B、嵌入图片B、JSON/其他B；预览与解码器另列 | 不能把Blend归档、网站海报和模型下载加在一起称模型体积 |
| 几何/CPU | 源/求值顶点，导出POSITION stream、tri、primitive；parse/decode/upload分开 | 去掉不可见细分或无用attribute；避免固定tri:B换算 |
| 纹理 | 每张角色、尺寸、编码B、mips、色彩空间、共享关系、RGBA8解码估计 | 256px不必强制；建议先试单张256/512原创建色图，再按可见贡献决定normal/ORM |
| GPU与场景 | 可见/提交实例、active LOD、draw calls、tri/各pass、shader/透明overdraw、framebuffer、阴影；实测帧时与设备 | 先区分CPU提交/顶点/填充/带宽瓶颈，再优化；SwiftShader只证明功能 |
| 编辑/恢复 | .blend、生成器、参数、原始贴图/烘焙等 | 保留可编辑性，不拿其大小挤占单个运行GLB预算 |

砂岩34,128B拆成几何bufferView31,752B、其他2,376B、图像0B。fern420,508B中几何417,216B；folded538,828B中几何532,848B、图像0B。它们的大小并非大纹理造成。数据以去重bufferView长度求和，不是GPU真实分配；共享bufferView可含多个流，不能重复收费。

三角龙轻量版相对优化plain428,496B只增加43,288B，却由9个primitive整合为1个；仍不能直接宣称9倍提速。其58,887B JPEG在512² RGBA8全mip假设下约1.33MiB；每张256²约0.33MiB、1024²约5.33MiB。三张1K/2K约16/64MiB，文件压小不等于显存小；实际压缩、共享、分配及driver开销须另记。

**纹理试行建议（待批准）：** 调色板资产可零贴图；常规单张512建色atlas按实际贡献允许至约100KB编码、约1.4MB RGBA8全mip估计；近看至多三张512分别核算，合计约4.2MB估计，软编码总量约250KB且仍受GLB总量约束；1K按单件申请，不自动上2K。透明贴图须额外看重叠、背面与远距闪烁。上述内存/数量是研究参考，不能偷偷替换当前1张256的冻结合同。

## 7. 必须看实物、但保持轻量的QA流程

**建模前，约10–15分钟为起始时间盒。** 找到一张可靠机构/原始来源的实物全貌照片和一张有助于结构/侧面理解的实物照片；可来自同一可靠页面，不机械要求两家机构。教学图可补充内部机理，不能冒充实物。制作人必须打开实际图片像素，记录URL、图/标本名、访问状态、观察到的2–3条形态原则、艺术简化及rights（只咨询不打包第三方素材）。可用独立机构的风格化图作为风格参考，但不代替实物。灭绝/不可拍到的完整形体，用实际化石/标本照片加明确标注的权威复原，并留下哪些外部形态未知。

打不开图片时换一个可靠来源；仍不可用就把“实物像素未查看”记为unknown并停该件brief_ready，或请用户明确接受教学/描述性范围。不能用搜索摘要+`consulted-only`把未知变PASS。不是要求下载/复用扫描或证明每块岩石的精确年代。

**便宜的第一轮结构检查。** 主壳和中尺度结构完成时，先出正反3/4、左右侧、顶面灰模小图；在80/128/240px正常大小看轮廓、重量、连接、层级和自然节奏；近看支持到480px再看480px。早发现像板材、管子、齿轮叶、堆圆锥，不等高采样漂亮海报才返工。明确当前缺陷和1–3个修正，不做全体随机噪声。

**最终独立QA，一次合并意见。** 使用冻结brief、参考ledger、exact GLB hash和实际GLB视图，不给制作者自评分引导。沿用8个有用固定视角：hero/reversehero/front/side/rear/top/clay/silhouette；薄片/悬空/洞穴有疑问时补底面或针对性角度，不普遍强制转台。必须点开关键原图并按正常像素大小查看，contact sheet用于导航，不能仅验证图片文件存在。灰模去色检查中尺度；纹理资产加一个材料正常效果与换光检查，避免高光遮丑。

**用途专检，只增加一张有意义的场景图。** 自然prop放在中性接地小景中，一件近看、3–9件不同朝向，检查侧背面、重复节奏和接地。指定高重复档另作固定代表性100副本压力场景，整组一次，不为每件重复搭场。教学剖面检查切面目的、内部读取和诚实标签；内部结构资产沿用灰模顶视识别例外，不强迫靠外轮廓认出化石痕迹。场景不暗示跨时代共存，不修改现有博物馆。

**技术照旧，审美另判。** 保留source/export、官方validator、可重复构建、冻结哈希、目标GLTFLoader/运行像素检查。功能与硬件性能分开。独立评审分别给技术、基本形态、自然场景观感/教学清晰度、交付、runtime的pass/fail/unknown及证据。每个硬问题须指出视角、可见缺陷及违反哪条用途义务；“我想更科学”不是普通prop返工理由。每件一次合并QA和最多一次计划修补；持续有真问题则hold，由负责人/用户决定缩用途或另开任务，不无限循环。

新流程的参考图片检查与现有8视图合并，**不要求每件论文、24–36帧高采样转台或真实设备全套性能巡回**。代表性的画廊/常规小景/高重复场景测一次并保留硬件边界；涉及shader、透明度、纹理档、instance策略或LOD的变化才触发相应性能复测。

## 8. 官方依据及适用边界

以下在2026-10-19通过网页检索/打开核查；数字软档是本提案自己的项目起点，并非这些来源给出的行业面数标准。

- [Khronos Real-time Asset Creation Guidelines v2.0 摘要（2025-08）](https://github.com/KhronosGroup/3DC-Asset-Creation/blob/main/asset-creation-guidelines/RealtimeAssetCreationGuidelines.md)：Geometry列出导出顶点拆分与几何/体积矛盾，Textures涉及mips、密度及channel packing。借用分账原则；不把产品数字孪生的写实精度强加给风格化自然资产。当前部分full-version章节为WIP，未把占位正文当已完成标准，也未访问其Drive工作稿。
- [Khronos Asset Auditor 官方说明](https://www.khronos.org/blog/khronos-gltf-asset-auditor)：允许按具体用例自定义Audit Profile，审计允许/偏好范围与格式validator互补。支持软参考与硬技术约束分开；网页3MB/30k只是示例，未采用为本项目限额。
- [Unity 6.6：Reduce rendering work on the CPU or GPU](https://docs.unity3d.com/6000.6/Documentation/Manual/OptimizingGraphicsPerformance.html)：先profile瓶颈，区分CPU命令提交与GPU填充/带宽/顶点；阴影、overdraw、剔除各自影响成本。借用诊断方法，不把Unity机制当Three.js已实现功能。
- [Epic：LOD Best Practices](https://dev.epicgames.com/documentation/en-us/fortnite/level-of-detail-lod-best-practices-in-fortnite)：屏幕占比阈值要按资产调整并实际缩放检查切换。只采用观看尺寸与验证原则；不照搬UEFN阈值、固定减半或其平台validator规则。
- [Three.js WebGLRenderer官方API](https://threejs.org/docs/pages/WebGLRenderer.html#info)：`info.render.calls/triangles`可记录实际提交；多pass时须正确reset。`info.memory`的textures/geometries是对象数量，不是显存字节，不能当GPU内存实测。
- [NPS Navajo Sandstone，实物照片与说明](https://www.nps.gov/zion/learn/nature/navajo.htm)：提供斜向层理实景与较远地貌照片入口（NPS/Adrienne Fitzgerald等署名），可作为下一版实物研究线索；不能拿一个地点的风成砂岩来限定所有交错层理成因。

**参考访问限制必须保留：** 本研究读到NPS页面及其图片URL，网页工具没有返回可供本环境检查的图片像素，本地下载又被网络代理403阻止；因此本研究**没有声称已经看过NPS实物照片**。本轮砂岩判断依据是仓库实际模型预览像素、生成器和冻结记录，不是虚构的照片对照。提案不受此阻碍，但实际重做样品前必须完成上述实物像素检查；这也是不能现在宣称新自然造型已获认可的原因。
