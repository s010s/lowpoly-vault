## Required fixes for all four candidates

These are package/specification findings; they do not call for changing the meshes or relaxing a threshold.

1. **References schema:** each `references.json` source lacks the required nonempty `license` field. Independent `python scripts/validate_candidate.py … --json` runs returned `valid: false` with these exact first errors: `IV-PRI-26.license`, `IV-ROM-PIRANIA.license`, `FL-bosworthia.license`, and `IV-ROM-HAPLOPHRENTIS.license: nonempty text required`. Bosworthia has a second source, `FL-bosworthia-form`, missing the same field. The repository template permits an honest **reference-only** value where source media is not incorporated; do not imply redistribution rights. The bundle `LICENSE.txt` covers the original asset and does not fill this per-source field. See [references.template.json](../../../../schemas/templates/references.template.json), each [frozen references file in Heliophyllum](https://github.com/s010s/lowpoly-vault/blob/03a6707e258b8e748cca04f5055311da019e6621/assets/candidates/continuous-small-life-round03-20261018/batch-08/heliophyllum/r001/references.json), [Pirania](https://github.com/s010s/lowpoly-vault/blob/7327e3cb1022028ca488ee8afe23c9b221a7628a/assets/candidates/continuous-small-life-round03-20261018/batch-08/pirania/r001/references.json), [Bosworthia](https://github.com/s010s/lowpoly-vault/blob/1d1196d2b12267ec6ee664e630da980ff690586a/assets/candidates/continuous-small-life-round03-20261018/batch-08/bosworthia/r001/references.json), and [Haplophrentis](https://github.com/s010s/lowpoly-vault/blob/d6b3b814603a327efa8dd05b33b699d67ba8f667/assets/candidates/continuous-small-life-round03-20261018/batch-08/haplophrentis/r001/references.json).

2. **Production render coverage:** every frozen brief sets `profile: production` and `turntable_frames: 0`; every render manifest also contains zero turntable frames. The unchanged validator requires at least **2** (`integer(..., minimum=2)`) and verifies the manifest has the planned distinct angles. The current eight-view set also omits the required production view names `left`, `right`, `bottom`, `wire`, and `detail`; `view_exemptions` is absent. The existing exact-GLB `near` image supports this review's moderate close inspection, but it is not a `detail` view in the frozen QA render manifest. Add hash-bound evidence for the missing view names and at least two distinct turntable angles, then re-run validation without changing checker thresholds. The current `coverage_justification` for fewer than 24 turntable frames is present. The exact validator requirements are in [`validate_candidate.py`](../../../../scripts/validate_candidate.py#L213).

The source `candidate.json` still leaves all seven required stage states `unknown` and approval `pending`. This review is recorded separately on the QA branch; after the metadata and evidence fixes, the candidate record must be validated and updated from the new immutable source/evidence hashes. The committed legacy project-checker reports are also `valid: false` on the missing source-license field.

## Technical and runtime results

- All entries in each bundle's `checksums.sha256` passed. The handoff GLB, Blend, brief, references, generator, config, render-manifest and runtime-manifest hashes matched the exact candidate tips.
- Fresh Blender 4.3.2 reopen/import comparisons matched triangle counts and bounds for source and exact GLB; source meshes had zero boundary/nonmanifold edges and finite normals. Imported GLB counts were 3,836 / 6,036 / 2,212 / 4,230 triangles. The clean GLB imports reported 128 / 144 / 0 / 80 boundary edges; every reported boundary edge had a coordinate-matched pair and **zero unpaired boundary-edge keys**. The original multi-view/runtime images show no visible opening or missing surface at these coincident edges.
- I reviewed the eight source-export smooth-face warnings (2 / 2 / 1 / 3 by asset) against the actual views. The smooth shading is deliberate on these rounded walls, spicules/ribbons and shell parts; I found no visual warning that needs mesh repair.
- The independent static GLB audit returned no errors or warnings under the unchanged brief budgets of 14,000 triangles, 6 materials and 30 primitives. The pinned Khronos glTF Validator 2.0.0-dev.3.10 independently returned **0 errors / 0 warnings** for all four exact GLB hashes. Raw outputs are in [gltf-validator/](independent-evidence/gltf-validator/).
- Exact-GLB images and manifests were SHA-verified and opened. Nine-copy scenes remained unclipped and readable at 512 px: 27 / 27 / 9 / 36 draw calls and 34,524 / 54,324 / 19,908 / 38,070 submitted triangles, in asset order above. The runtime used Chromium 154, Three r180 and ANGLE SwiftShader; its timings are software observations, not a physical-device performance claim.

No candidate asset, brief, validator threshold, CI setting, permission or release branch was changed. No merge or Drive upload was made. The current candidate branches remain pending the fixes above.
