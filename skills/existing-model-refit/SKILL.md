# 旧模型筛选与改造

目标是用最小必要改动解决当前版本的可见问题，而不是给全库补贴图。默认采用轻量贴图组合、按实际用途增加通道；结构缺陷不能靠表面掩盖。先筛选，再执行被授权的具体项。本目录是仓库本地 Skill，并非全局已安装技能；派发时显式传入本文件与相关引用路径。

## 1. 只读确认现状，给出短名单

- 从本次工作区的现行 manifest、registry 与发布记录交叉确认资产 ID、revision、实际可加载的 GLB、可编辑源、哈希、来源/许可证、既有验收范围和限制。目录名或旧报告不证明已完成/已上线；本地与线上状态分开写。输入有冲突先列 UNKNOWN，不猜“最新版”。
- 实际重载当前 GLB 看支持观看范围下的画面，检查轮廓、连接、比例、材料分区与表面表达。只有源截图或文件存在，不能证明交付 GLB 可用。记录看过的角度和未覆盖面，不扩充原合同的角度数量硬门。
- 按下表逐项判定，按问题可见性、用户用途与预期改善价值排序，同时考虑成本、依赖和风险。没有新图片纹理不是缺陷，不自动全库重做，也不把历史样本的缺陷移植给当前版本。

| 判定 | 适用情况 | 下一步 |
| --- | --- | --- |
| KEEP | 当前用途已满足，收益不足或无确定缺陷 | 保留原版，写清适用范围 |
| 表面改造 | 结构合格，颜色/材质可读性值得改善 | 最少必要贴图或材质变化 |
| 几何修复 | 有局部轮廓、连接、厚度或起伏问题 | 先修结构，再按需调整表面 |
| 重做 | 现有结构不适用，局部修复价值低 | 提出具体替代范围与成本，获授权才执行 |
| HOLD | 版本、源、许可、锁、预算或关键证据未确定 | 说明解除条件；保留失败与 UNKNOWN |

筛选结果用短表即可：资产/revision、GLB与源证据、实际可见问题、判定、优先理由、授权与阻塞。只读筛选不授予制作、上传或替换权限。

## 2. 冻结单项合同后才修改

准备具体项时使用 [单项记录模板](references/refit-record.md)，不替代仓库已有 schema 或主账。2026-10-29 本轮的两个旧改试制须另读 [本轮唯一试制合同](../../docs/trials/lighttexture-four-20261029.md)，冻结其中旧改额度与表面范围；该临时合同不作为以后所有旧改的默认预算。确认：

- 当前 GLB、源与验收证据的 baseline 路径及 SHA-256；原版只读保留。副本输出到独立的新 revision/attempt 目录，不覆盖历史输入或伪装成原版。
- 本次允许改变的内容、明确不做的内容、目标观看范围、预期可见差异与失败/停止条件。表面-only 不偷偷包含几何重建；新增 UV/基础法线准备变化也须披露，改变范围先核对授权。
- 逐项记录适用的用户授权及其对象、阶段和边界。可以沿用覆盖本次工作的既有合同，也可以采用用户新批准的独立改造合同；后者单列授权、scope 与新预算，不删除、重置或冒充原合同历史。授权已覆盖则在范围内执行，不反复索要同一许可；缺失则停在方案。筛选、实际修改、验收、上传、合并、部署分别判定权限；平台必需审批不能免除。
- 读取本项既有实际改动预算、已消耗次数、attempt、失败历史、锁与 UNKNOWN。不得把旧项套进新制默认“1 次制作 + 1 次验收”以刷新次数；改目录、改名、换 Maker 或称为贴图优化均不重置预算。本次一次实际改动的起点与内容须在动手前记录；不把多轮重建包装为同一次，也不把只读筛选计为已制作。
- 所选有效合同的预算不明、已耗尽或适用锁未解除则 HOLD，说明所需具体授权。原合同耗尽不自动否定用户明确另批的新独立改造合同；旧失败/锁仍需保留并核对新授权是否处理其限制。一次执行未通过时保留失败输出，不无限试做；仅在当前明确授权的合同仍有额度且范围覆盖时继续，不以“新合同”自行制造额度。

## 3. 做一个必要的新候选

共用新制管线的质量标准（见下方共享规范），但使用本项已冻结的有效改造合同、预算与验收范围，不继承新制预算。先确认当前 GLB 原样重载无工具链颜色/缺图问题，再改副本。

结构可靠时从材质因子、清楚的颜色分区或小型颜色图起步；法线/粗糙度仅在支持距离有可见用途时增加。结构有问题先修结构，不用噪声、AO 或高光遮盖连接缺失。保持纹理方向与对象组织一致。无收益时保留无图版本也是有效结果。

不要求每项跑多档尺寸、全通道矩阵或复杂四版本实验。只制作满足问题定位和验收所需的候选；诊断确需额外实验时先核对预算/范围。图集或共享材质牵连其他资产时列出影响，不借单项任务改全库。

## 4. 同条件比较与 fresh QA

Maker 与 fresh QA 必须不同。QA 先看原始依据、冻结候选的真实 GLB 和证据，再看 Maker 结论，不复述 Maker 的“通过”。对照使用当前 baseline 和新候选实际 GLB 重载后的截图，同角度、灯光、曝光、视口与尺度；如无法同条件，说明偏差，不能声称单一变量净提升。

提交关键差异图和简明前后表：revision/哈希、几何指标、GLB bytes、使用中的材质/primitives、每张贴图的角色/尺寸/格式/bytes、保留或删除理由；注明导出兼容、可编辑源、来源许可、格式检查、视觉结论与未测局限。总字节减少不等于画质通过、GPU 内存减少或帧率提升；未测设备/角度仍为 UNKNOWN。改变交付字节后，相关旧验收不能平移。

QA 给出 KEEP 原版、候选在明确范围通过、失败或 HOLD，并列出实际可见收益和代价。通过只表示该候选在记录范围合格，不自动覆盖旧版、改发布清单、上传 GitHub、解除草稿、合并或部署；这些动作须有对应具体授权、通过相关检查并满足必需审批。

## 共享规范与历史参考

执行改造前读 [共用轻量贴图质量规范](../lowpoly-lighttexture/references/lighttexture-profile.md)：沿用其结构可信、UV/通道、真实 GLB、格式与画质证据要求。默认尺寸和编码只是起点，不是硬阈值；不继承 [新制 Skill](../lowpoly-lighttexture/SKILL.md) 的调度模板或 `normal-new-original1plus1` 预算。共用 `../../scripts/lighttexture_profile.py` 可只读报告新候选的贴图/UV/字节；它不替代官方校验、真实加载和 fresh QA。旧 baseline 的既有扩展若不在该窄工具支持范围，应保留既有检查路径并注明工具限制，不改旧字节迎合工具。

历史方法依据：`texture-experiment-review/inspection/internal/asset-pipeline-20261029/` 的 `legacy-retrofit-plan.md`、`experiment-record.md` 与 `texture-craft-and-budget.md`（工作区资料，可能不随仓库分发）。仅在需核对实验依据时读取；缺失不妨碍本 Skill 的筛选流程。其历史 16 项、样本尺寸、bytes、多档实验和有限角度判断均不是当前库事实、统一预算或发布批准。
