# Meshy 底模 → Blender 生物精修

将生成结果视为可编辑底模，而非成品。先判断形体是否值得保留，再做局部精修、分区减面与必要贴图；以实际导出的 GLB 和目标观看用途判断成果。

## 确认本次目标

使用任务已有的物种研究、设计图和版本记录，不要求重新搜集同一份资料。补查影响本次形体判断的缺口；区分科学依据、艺术选择和不确定部位。图片与第三方资产的查阅权不等于再分发权。

明确用途、物种/风格、允许的简化、观看距离、几何与文件软预算，以及本次允许的生成次数、积分上限和修改范围。授权已覆盖就执行，不反复索要同一许可；只要求看方案时，不调用付费生成。发布与模型制作分别核对授权。

按 [任务配置与记录](references/task-configuration.md) 参数化运行环境和交付位置。本地、远程或云端均可采用；此流程不指定存储服务、个人设备或代理型号。凭据由执行环境的安全机制提供，不写入配置示例、日志或资产包。

## 1. 准备有效输入

- 使用同一设计、比例与姿态相容的清晰独立视图。检查主体、头部和识别特征的实际像素；一张大画布或四张图不自动代表信息充分。
- 不把低分辨率拼图切片、插值放大当作新增细节。先解决视角矛盾、遮挡和变形，再决定是否需要更多图。
- 保留原图、处理记录和视图顺序；生成图可指导美术，不能证明物种事实。优先复用适用且权利清楚的来源，而非每只重新造一套研究。

## 2. 生成并保留底模

调用前读取 [Meshy 接入要点](references/meshy-api.md)，复核当前参数和预计费用。若计划在 Blender 制作表面，可从不带贴图的 Standard 底模试起；这是节省试验成本的建议，不是所有项目的强制默认。高精度模式须有具体待改善问题和预算，不能只因“更贵”而升级。

为每次尝试记录输入哈希、非敏感参数、任务状态、服务端任务 ID、预计/实际积分和产物哈希。创建任务后及时持久化 ID；轮询、下载失败重试同一任务，不重复创建。

POST 超时或结果不明时先对账，不能盲目再次 POST。明确失败、已对账或主动改进的下一轮可以在现有授权与剩余额度内执行；说明改变什么、期望改善什么。未知扣费保留待核，不按零处理；达到上限或剩余授权不足时暂停并说明所需决定。保留历史失败，但不将一次失败永久锁死后续获批修订。区分“候选质量待修”与“任务明确暂停/审批待办”：前者可在已授权范围继续，后者先解决具体阻断。

## 3. 先修形体，再决定表面

先真实重载下载的底模，以中性灰材质检查全身轮廓、头颈/肩胯过渡、肢根、关节、承重、口腔及其他关键结构。选择最小有效路线：

| 现状 | 路线 |
| --- | --- |
| 当前用途已满足 | 保留；不为了统一流程强制重做 |
| 形体可信，仅颜色/材质弱 | 表面修整；无需再生成底模 |
| 问题局部、主体可用 | Blender 局部修复，再按需处理表面 |
| 关键比例/结构普遍错误 | 改善输入后重生成，或人工重建；核对剩余范围与预算 |

参考 [Blender 精修与验收](references/blender-and-qa.md) 完成形体修改、分区减面和轻量贴图。保护识别轮廓、薄结构、口眼与关节；不要统一比例减面或用噪声贴图遮盖缺陷。按用途接受有意识的低模取舍，不自动要求影视级眼球、牙列或皮肤。

## 4. 独立检查真实交付物

保留可编辑源和原始底模，导出独立 GLB。制作与独立 QA 分离；复核者先看任务目标、来源、精确 GLB 和实际证据，再看制作者结论。没有独立复核条件时，可交付自检结果但明确独立 QA 待完成。

在干净场景重载该 GLB，查看约定范围的灰模、材质和必要局部；最终预览来自此 GLB，不用概念图或源场景截图替代。几何、材质或导出字节改变后重查受影响项，不把旧结论直接移给新文件。

分别记录格式/技术、可见形体与材质、事实依据、目标运行环境结果。预览通过只说明已看范围；未测浏览器、动画、设备或角度标待完成，不冒充失败，也不冒充已通过。向目标应用交付前补齐该用途必需的加载与性能检查。

## 交付与迭代

交付原始底模、可编辑源、最终 GLB、必要贴图、来源与许可、关键设置、精简费用/时间记录及验收结论。分别列 API 处理、下载等待、制作墙钟与实际记录到的操作时间；无连续计时就不推算净工时，不以一个样本承诺批量速度。

用简短结论说明可见收益、剩余问题、实际代价和下一步。只为有证据的问题追加实验，复用未变的研究和有效检查。质量通过不自动允许覆盖原版、推送仓库、合并或部署；按当前任务的实际授权执行。
