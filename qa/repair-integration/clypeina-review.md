# Clypeina: single-value material adjustment

Four native-shader azimuths and an unlit color control show near-black disc junctions reducing the readability of radial grooves and pores, notably at 90° and 270°. Setting the original glTF default metallic value of 1 to .65 restores those features without flattening the natural darkness in the concave and shaded parts. No geometry, pose, fit, lighting or texture changes.

- Original GLB SHA-256 1f6d912d0e0d18575e09b2c40bd1353bbb8b6e0963f8ef4d0baa126fcfd27427; candidate 70c45e001d61736cb4116e33d6bbef35399b7698dbfc5370fa4260832e987cae. One GLB JSON PBR parameter was added; the rest of the parsed JSON and the entire BIN chunk are unchanged. Original and candidate had zero validator errors or warnings. The native packed Blend received the matching one-value adjustment, and reopened Blender geometry, matrices, UVs, texture pixels and packed data matched the candidate import.
- The existing production binaries and both posters were verified against those actually delivered. New source-bound wheel and detail PNGs were redrawn from the revised GLB. Held canonical poster and stable exact-GLB endpoints on 1440×1000 and emulated 390×844 used the same framing and colors. Candidate desktop/mobile CDP samples were 28/42 with two reverse mobile timestamps; this is finite endpoint evidence, not continuous frame-order or physical-device certification.
- At emulated 370×710 English, the deployed layout covered the lower disc (1,570 of 24,360 projected vertices). The shared mobile-flow revision in the repair base had zero overlapping geometry on the original and revised materials, with approximately 91 CSS px to the toolbar. No model-specific layout changes.
- Each scoped build passed eight targeted interactions, four actual GLB/Blend downloads, both actual poster response hashes per viewport, and regenerated ZIP/credits checks. This is not a full production build, general device certification, or release approval.
